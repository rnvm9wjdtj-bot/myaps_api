# ATTENTION — 外部系统连接组件开发规约

> 2026-10-08 畅捷通 T+ 库存拉取丢数据（实取 3000/7100，同物料多库位只留一条）暴露出一类共性陷阱。本文件把根因抽象为模式与检查清单，供在 `apps/data_opt/components/` 下**新增 ERP/外部系统连接组件**时规避。新增组件接入后，把新踩到的语义陷阱补到本文件。

## 一、根因模式（抽象）

外部系统拉取丢失，几乎都来自「代码假设的接口语义 ≠ 服务端真实语义」叠加「静默吞错」。典型表现：拉取数稳定少于实际、同维度多记录只留一条、无报错无告警。

1. **分页机制混用**：同时使用页号（PageIndex）与游标（Ts/cursor）两套分页。若游标实为「过滤条件」，服务端会在不断收缩的集合上继续按页号取数，页号很快越过末尾返回空 → 循环 break → 剩余记录全丢。
2. **游标取值依赖返回顺序**：取 `raw_data[-1]` 而非 `max(cursor)`；返回未按游标排序、或同游标值有多条时，会跳过/重复。
3. **空页即结束，不区分原因**：限流/超时/降级返回空与「真结束」无法区分，静默 break 丢后续页。
4. **非预期响应当列表遍历**：业务错误体（dict）被当 list 遍历 → 报错或静默丢。
5. **HTTP 4xx 静默**：只对 5xx 抛错，401/403/429 返回错误体被当数据。
6. **请求封装返回契约不一致**：封装已返回解析后 JSON，调用方再 `.json()` → AttributeError；或封装返回 Response，调用方当 JSON 用。
7. **classmethod 内嵌套函数误用 self**：触发 NameError，被 `except: return []` 吞掉 → 整批数据静默为空。
8. **并发异常静默吞掉**：`gather(return_exceptions=True)` + 内部 `except return []` 把确定性错误降级为「空数据」。
9. **全量替换无对账兜底**：刷新采用「先 DELETE 再 upsert」，拉取少一条则库里少一条且旧值已删，无对账则不可见。
10. **展开/聚合后用错对账基数**：用展开后行数对账 TotalCount（原始记录数），会提前终止翻页。

## 二、新增连接组件 Checklist

接入新 ERP/外部系统拉取前，逐项确认（**语义类必须实测，不要靠文档/猜测**）：

### A. 分页语义（必实测）
- [ ] 服务端支持哪种分页：页号（PageIndex/PageSize）、游标（Ts/cursor/scrollId）、还是两者叠加？写最小脚本分别「只传页号 / 只传游标 / 都传」对照返回集合。
- [ ] 游标参数是「过滤条件」还是「分页游标」？若是过滤，翻页时**不可**同时递增页号。
- [ ] 翻页只用**一套**机制；游标取 `max(cursor)` 而非最后一行；同游标值多条需去重收敛。
- [ ] 终止条件：空页 break 之外，优先用响应里的 `TotalCount`/总数对账提前停止。

### B. 响应契约
- [ ] 响应是顶层 list 还是 `{Data:[...]}`？统一用 `isinstance(dict) and 'Data' in resp` 判断，不要裸 `try/except`。
- [ ] `SelectFields`/字段投影是否影响返回**维度/聚合**（而非仅裁剪列）？实测含/不含维度字段时行数是否变化。
- [ ] 请求封装（`_post/_get`）返回的是已解析 JSON 还是 Response 对象？全模块统一，调用方不再二次 `.json()`。

### C. 错误处理
- [ ] HTTP `>=400` 统一抛错（4xx 不能静默）；重试码白名单与封装重试策略对齐，避免 401/403 无效重试。
- [ ] 业务错误码（`code != 0`）在拉取层校验或告警，不要把错误体当数据遍历。
- [ ] 非列表响应：告警 + 终止，不遍历 dict 的 key。
- [ ] `classmethod` 内嵌套函数用 `cls`，不要用 `self`。
- [ ] `gather(return_exceptions=True)` 的异常要显式 `isinstance(x, Exception)` 上抛或告警，不要 `return []` 静默吞。

### D. 完整性对账
- [ ] 拉取后用 `TotalCount`/总数对账，不一致 `logger.warning`。
- [ ] 对账基数用**原始记录数**，不是展开/聚合后的行数。
- [ ] 全量替换式刷新（先 DELETE 再 upsert）必须有对账兜底，否则拉取缺失会被静默固化。

### E. 复用与回归
- [ ] 底层拉取方法被多个 Source 复用时，新增 Source 接入前确认其分页语义与该方法假设一致。
- [ ] 改动共用方法后，所有调用方回归；新增 `tests/test_<component>_paging.py`（假连接、不触网/不触库）覆盖翻页/对账/异常。
- [ ] 未启用/备用组件类同样要正确（一旦 `register_source` 启用即触发）。

### F. 验证手段
- [ ] 用真实凭证直连做**只读**对照实验确认语义；脚本里设置本地「认证时间」避免 token 刷新写配置，`cache_file=None` 断开写关联，严禁改动数据库。
- [ ] 上线前测试环境验证；运行时改动需重启服务。
